Engine prototype

Sable

C++23 · OpenGL · ECS

A game engine prototype built around explicit data layout and a separation between game data, systems, and rendering. Entities with the same set of components are grouped into archetypes and stored in 16 KB chunks; bitset signatures select the groups a system needs.

Within a chunk, each entity’s attributes occupy a contiguous block. Removing an entity moves the last entity into the vacant slot to keep storage dense. Systems have explicit priorities for update phases, making the order of simulation and rendering visible in the engine API.

The rendering pipeline separates imported assets from GPU resources. Models are loaded through Assimp, uploaded through a resource manager, and submitted in groups sharing a shader program. Scene, UI, and texture cameras support multiple passes; the Trains example combines generated terrain, rail routing, resource delivery, and a minimap.

Embedded systems project

athreads

C · AVR assembly · ATmega2560

A small preemptive threading library for an 8-bit AVR microcontroller. Timer1 drives round-robin scheduling, while assembly routines save registers and the stack pointer before switching to another thread. Each thread has an explicitly allocated stack and its own configurable time quantum.

The scheduler supports yielding, tick-based sleeping, and waking threads back into the ready state. Per-thread CPU counters expose how execution time is distributed, and the quantum can be changed while the system is running.

An optional profiling demo sends binary samples over USART to a Python viewer. An OLED and rotary encoder provide a second way to inspect threads and adjust their quanta on the board. Together, these make the scheduler’s behavior observable alongside the low-level context-switch implementation.

Systems prototype

Market Simulator

C++20 · Linux · TCP / UDP

An exchange-style simulator that connects an in-memory limit order book to separate order-entry and market-data services. The matching engine uses price-ordered maps and FIFO lists within each price level to model price–time priority, including partial fills and trade attribution to both orders.

The order lifecycle includes server-assigned IDs, cancellation, and modification. Quantity reductions retain their position; price changes or quantity increases follow a cancel-and-replace path. The implementation keeps this domain logic separate from the network services.

Clients submit commands through a length-prefixed TCP protocol handled with epoll. A UDP multicast service distributes book snapshots to subscribers, and a sample client exercises the command and feed paths. This experimental simulator includes GoogleTest sources covering matching, cancellation, modification, and trade lookup.

Operating Systems coursework

Parallel Firewall

C · POSIX threads · Synchronization

A producer–consumer exercise for processing simulated network packets with multiple worker threads. The producer writes packets into a shared circular buffer; semaphores track available and occupied slots, while mutexes coordinate shared state.

Workers compute packet decisions concurrently, then use a sequence number and condition variable to emit log entries in input order. This separates parallel packet processing from ordered output and makes the synchronization requirements explicit. The repository includes a serial reference and test tooling.

Communication Protocols coursework

Router Dataplane

C · IPv4 · ARP · Tries

A software router dataplane covering Ethernet, IPv4 forwarding, ARP resolution, and ICMP responses. The routing table is converted into a binary trie at startup; lookup follows destination-address bits and retains the longest matching prefix.

The forwarding path checks the IP checksum, handles TTL expiry, updates headers, and resolves the next-hop MAC address. Packets wait in a queue while an ARP request is outstanding and are reconsidered when a reply arrives. ICMP handles echo requests and reports unreachable destinations or expired TTLs.

Operating Systems coursework

Memory Allocator

C · Linux memory management

A minimal implementation of malloc, calloc, realloc, and free equivalents. Small allocations use the process heap through sbrk; larger allocations use mmap and are returned with munmap. Allocation metadata tracks block size, status, and neighboring blocks.

The allocator handles alignment, reuses free blocks, splits oversized blocks, and joins adjacent free regions. Reallocation attempts to resize an existing heap block before allocating elsewhere and copying data. The supplied test harness compares allocation behavior and system calls with reference cases.

HTTP Client

C++ · HTTP · Sockets

A small HTTP client library and command-line application for a supplied server API. An HttpSession owns reusable headers and cookies, builds requests, and parses responses; a separate HttpConnection handles the socket transport.

The client exposes GET, POST, PUT, and DELETE operations. Response handling separates headers from the body and uses Content-Length to complete reads. Supporting utilities provide status/error values, logging, input parsing, and JSON integration.

Subscription Messaging App

C++ · epoll · TCP / UDP

A publish–subscribe server connecting UDP message producers to TCP subscribers. Clients register with an ID, subscribe or unsubscribe from topics, and receive matching messages with the sender’s address information.

The server multiplexes sockets with epoll and keeps client profiles across disconnects. Topic matching includes wildcard patterns, while a length-prefixed command protocol distinguishes subscription requests from delivered messages. The project brings together connection management, framing, and message routing.

Systems coursework

MiniLibc

C · Linux system calls

An educational subset of the C standard library built over Linux system calls. The repository covers file I/O, memory mapping and allocation, process exit, sleep, and string operations, alongside startup code and syscall wrappers.

The implementations show how familiar interfaces translate into lower-level operations—for example, open forwards to a syscall and translates negative results into errno, while allocation is backed by memory mappings. Its deliberately limited scope keeps the syscall boundary and library responsibilities visible.

Algorithms & graphics

Algorithm study

Knapsack Algorithms

C++ · Dynamic programming · Approximation

A comparison of several approaches to the 0/1 knapsack problem: exhaustive search, dynamic programming indexed by weight, dynamic programming indexed by profit, and a profit-scaling approximation approach.

The profit-based formulation stores the minimum weight needed to reach each profit. The approximation implementation scales profits before applying that recurrence, exposing the trade-off between state-space size and solution accuracy. Versions with and without solution reconstruction are included, together with Python input-generation and timing scripts.

Programming coursework

Octave Simulator

C · Matrices · Strassen multiplication

A command-line matrix workspace written in C. It keeps a dynamically resized collection of matrices and supports loading, selection-based resizing, multiplication, transposition, exponentiation, sorting, and deletion.

Alongside ordinary multiplication, the code implements Strassen’s decomposition into submatrices and intermediate products. The project combines matrix algorithms with explicit allocation and cleanup, rather than delegating the operations to a numerical library.

Numerical experiments

Numerical Methods Sandbox

Python · NumPy · Linear algebra

Small implementations exploring eigenvalue and singular-value computations. A power-iteration routine repeatedly multiplies and normalizes a vector, with a residual-based stopping condition and iteration limit.

The eigenvalue experiment applies rank-one deflation to extract further pairs. A separate SVD experiment constructs singular values and vectors from these computations. The scripts are exploratory implementations for understanding these methods.

Graphics experiment

Voronoi OpenGL

C++ · OpenGL · GLSL

An animated Voronoi visualization with moving seeds. Each seed supplies a position and color, and the fragment shader writes distance into the depth buffer so the nearest seed determines the visible region.

The shader contains several distance functions to explore how the partition changes with the metric. Seed movement is updated over time and reflected at the window boundaries. The animation can be paused to inspect the resulting geometry.

Data Structures coursework

Segregated Free Lists

C · Linked lists · Memory simulation

A heap simulation organized into free lists for different block sizes. A command interface initializes the heap, allocates and frees blocks, reads and writes simulated memory, and prints a memory dump.

The implementation uses doubly linked lists to manage blocks and records allocation statistics. It exercises splitting and free-list organization without replacing the host process’s allocator.

Small library

Container Library

C · Macros · Dynamic arrays

A single-header, macro-based implementation of typed dynamic arrays in C. A declaration macro generates the container type and its creation, destruction, access, and resize functions.

Capacity grows to a power of two, and allocation functions can be overridden through macros. The focus is a reusable container interface without C++ templates or a separate compiled library.

Image Editor

C · NetPBM · Image processing

A command-line editor for grayscale and color NetPBM images, supporting both text and binary formats. An active selection controls where transformations apply, so multiple operations can be composed before saving.

Operations include cropping, quarter-turn rotation, histograms, histogram equalization, and convolution filters for edges, sharpening, box blur, and Gaussian blur. Image storage, loading, command parsing, and filter logic are separated into modules.

Learning experiment

Simple Machine Learning

C · Neural networks · Numerical gradients

A small neural-network implementation written to understand training mechanics. It estimates a local cost gradient by perturbing individual weights and biases, then updates the model using those estimates.

The code separates neurons, layers, network configuration, and training data. It uses finite differences rather than backpropagation and favors a direct view of the computation over efficient matrix operations.

Developer tool

cfr — Codeforces CLI

Go · CLI · Competitive programming

A command-line helper for preparing and testing Codeforces solutions. It loads a contest, creates a directory for each problem, downloads statements and sample cases, and keeps contest state in local files.

The test command compiles or runs solutions in C++, C, Go, or Python and checks sample or custom inputs. Per-problem language selection and source backups make it possible to switch languages while retaining previous work.

Go · React · TypeScript
